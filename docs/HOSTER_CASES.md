# 호스트별 파싱 및 실패 처리 (v2.16.59)

이 표는 현재 코드의 동작 범위다. `지원`은 모든 공유 링크의 성공을 뜻하지 않는다.
호스트가 삭제, 권한 부족, 캡차, 회선 제한을 반환하면 파서는 그 이유를 기록하고 중단한다.
사용자 화면에는 번역된 원인과 조치만 표시한다. HTTP 응답, 내부 상태 문자열, 예외 원문은 진단 로그에만 남긴다.
현재 제공하는 18개 언어에 공통 실패 안내가 있으며, 한국어·영어에는 확인된 호스트 원인을 더 자세히 표시한다.

| 호스트 | 파일 정보 | 다운로드 주소 얻기 | 확인된 중단 조건 |
|---|---|---|---|
| 1fichier | 슬롯 차례에 조회, 받은 정보 재사용 | 무료 계정/회선으로 순차 발급 | 삭제, 로그인, 일일 한도, 슬롯 혼잡, 회선 차단, 대기시간 |
| MEGA | 공개 링크 메타데이터 | 공개 링크 복호화 | 삭제, 대역폭 한도, API 오류 |
| MultiUp | 페이지에서 이름·크기 | GoFile → MegaUp → MixDrop 지원 미러를 각 1회 | 미러 없음, 목록 구조 변경, 각 미러의 실제 실패 |
| MixDrop | 페이지에서 이름·크기 | 브라우저 무료 다운로드 흐름 | 삭제, 캡차/버튼 실패, 광고 이동 |
| MegaUp | 페이지에서 이름·크기 | 무료 링크와 토큰 이동 | 삭제, 링크 추출 실패, 페이지 제한 |
| DataNodes | 페이지에서 이름·크기 | API 또는 브라우저 Turnstile | 삭제, 캡차, 노드 접속 실패 |
| GoFile | API 응답에서 조회 | 시간 기반 웹 토큰과 공개 파일 링크 | 삭제, 다중 파일 폴더, 권한, 토큰 거부, 조회 속도 제한 |
| Send.now | 페이지 응답 | HTML 링크 또는 브라우저 흐름 | Cloudflare/Turnstile, 링크 발급 실패 |
| MediaFire | 페이지에서 이름·크기 | 페이지의 파일 링크 | 삭제 확인, 링크 추출 실패, 보안 페이지 |
| Pixeldrain | 공개 API | 단일 파일(`/u/`) 주소 | 파일 없음, 앨범(`/l/`) 또는 잘못된 ID |
| Bunkr | 페이지 응답 | CDN 링크 | 삭제 확인, 암호화 CDN 링크 미해석 |
| VikingFile | 페이지에서 이름·크기 | 사이트별 브라우저 흐름 | 캡차 또는 링크 미발급 |
| AkiraBox | 페이지에서 이름·크기 | 브라우저에서 짧은 수명의 주소 발급 | 파일 서버 사용 불가, 링크 미발급 |
| Rootz | 첫 페이지 응답의 파일 정보 재사용 | 활성 파일에 한해 다운로드 주소 확인 | 삭제, 비활성, 비밀번호, 무료 제한, 주소 거부 |
| DataVaults | 공개 페이지에서 이름·크기 | 자동 발급 불가 | 무료 다운로드의 reCAPTCHA v2 사람 확인 |
| Rapidgator | 페이지에서 이름·크기 | 무료 자동 다운로드 미지원 | 500 MB 초과 파일의 무료 제한, 캡차/계정 절차 |
| FileCrypt | 미지원 | 미지원 | 링크 컨테이너 앞 사람 확인 단계 |
| MomeryBox / TeraBox | 미지원 | 미지원 | 공유 페이지 이동 후 로그인 요구 |

## 파싱 실패의 처리 원칙

- **명확한 삭제 응답**: 즉시 종료한다. 일반 HTTP 404만으로 삭제를 확정하지 않는다.
- **캡차·권한·호스트 거부·파서 구조 변경**: 자동 재시도와 프록시 순회를 중단한다.
- **프록시 연결 자체의 일시 오류**: 같은 작업에서만 다른 프록시를 제한적으로 시도한다. 파서 시간 초과 시 기존 실행이 남아 있을 수 있으므로 새 파싱을 겹쳐 시작하지 않는다.
- **대기열**: 실패 횟수를 쓰지 않고 순서를 기다린다. 사이트별 브라우저 파싱은 한 번에 하나다.
- **다운로드 노드 장애**: 전송 단계의 제한된 복구만 허용한다. 이미 확인한 파일명·크기를 다시 조회하기 위한 요청은 하지 않는다.
- **MultiUp**: 지원 미러를 각 한 번씩만 확인한다. 복합 실패에서 한 미러의 삭제를 전체 파일 삭제로 표시하지 않는다.

호스트 파서 등록은 `backend/core/hoster_parsers.py`, 오류 분류와 재시도 정책은
`backend/core/error_messages.py`, 다운로드 동시성은 `backend/core/download_core.py`를 기준으로 한다.
