## 대기열과 실패 처리

- 사용자가 설정한 호스트당 수는 상한이다. 무료 1fichier/Rapidgator는 1개, 실제 3개 겹친 전송을 끝까지 확인한 GoFile/Viking는 최대 3개다. 나머지 1개는 보수적 시작값이며 무료 서비스 자체의 확정 한도와 구분한다. 별칭과 실제 저장 서비스는 같은 슬롯을 사용한다.
- 메타데이터 조회와 파일 주소 발급도 자기 차례에만 실행한다. 큐 대기와 호스트 대기시간은 요청·실패 횟수를 소비하지 않는다. 거부 응답의 대기시간과 명시적 단일 전송 제한은 DB에 저장하여 재시작 뒤 복원한다.
- 캡차·권한·403·파싱 실패에 자동 재시도/프록시 순회 없음. 실제 Cloudflare GET 확인 화면일 때만 FS 1회; download POST 반복 없음. 쿠키·UA·파싱 및 파일 전송 회선을 일치시킨다.
- 404/410, File Not Found, 구조화 deleted, 로그인 이동, timeout은 파일 삭제 확정과 다르다. 다운로더 실패와 원본 링크 상태를 분리하며 원본 자동 삭제·숨김·비활성화 없음.
- MultiUp/FileCrypt/Linkcuy/OUO는 컨테이너다. 목록 추출, 실제 호스트 주소 발급, 파일 첫 바이트, 전체 전송을 각각 기록한다. 다중 파일은 사용자 선택이 필요하고, 미러 자동 난사나 다른 BASE/파트 교체는 하지 않는다.
- 일반 HTTP는 파일 GET 한 번으로 헤더와 이름을 얻고 HTML/API 오류를 저장 전에 거부한다. Google Drive 공개 단일 파일은 실제 게시된 동일 ID 확인 폼만 한 번 이어받는다. 로그인·쿼터·폴더를 파일처럼 완료 처리하지 않는다.
- GoFile는 등록/API 키 없이 정상 무료 웹 경로를 쓴다. 현재 GoFile·Send.now·Rapidgator 등 내장 브라우저 파서는 Docker 환경이 필요하다. Windows에서 외부 FlareSolverr를 연결할 수 있는 것과 내장 브라우저 호스트 전체 지원은 별개다.
